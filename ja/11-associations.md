# 11 連想

MIT Scheme は、オブジェクトどうしを連想させるいくつかの仕組みを提供します。これらの
仕組みはそれぞれ、**キー（key）**と呼ばれる1つ以上のオブジェクトと、**データ（datum）**
と呼ばれる別のオブジェクトとのあいだにつながりを作ります。しかし、この共通の考えを
超えて、各仕組みはさまざまに異なる性質を持ち、それぞれ異なる状況にふさわしくなります。

- **連想リスト（association list）**は Lisp のもっとも古い連想の仕組みの1つです。ふつうの
  ペアから作られるので、組み立てと操作が簡単で、使うのに非常に柔軟です。ただし、連想
  リストの平均探索時間は連想の数に対して線形です。
- **1次元表（1D table）**は非常に単純なインタフェースを持ち、使いやすく、そのキーが
  ガベージコレクタに回収されるのを妨げないという特徴を提供します。連想リストと同様に、
  平均探索時間は連想の数に対して線形ですが、1次元表はそれほど柔軟ではありません。
- **連想表（association table）**は、Lisp の属性リストに対する MIT Scheme の等価物です。
  キーが任意の型のオブジェクトでよいこと、キーがガベージコレクタに回収されるのを妨げ
  ないことが利点です。ただし、2つの線形時間の探索を、各キーに1つずつ行わなければなり
  ません。伝統的な属性リストでは、両方のキーに対して1つの探索しか要りません。
- **ハッシュ表（hash table）**は、大量のデータに定数時間でアクセスできる強力な仕組み
  です。ハッシュ表は連想リストほど柔軟ではありませんが、アクセス時間が表の連想の数に
  依存しないので、ほとんどのアプリケーションで選ばれる仕組みです。
- **平衡二分木（balanced binary tree）**は、キーが順序づけられたアプリケーションに役立つ、
  もう1つの連想の仕組みです。二分木は、木の連想の数の対数に比例するアクセス時間を持ち
  ます。ハッシュ表ほど速くはありませんが、木の内容を線形時間でソート済みの alist に変換
  できる利点を提供します。加えて、2つの木を最悪でも線形時間で等価性について比較できます。
- **赤黒木（Red-Black tree）**は平衡二分木の一種です。実装は、良い定数係数を持つ破壊的な
  挿入と削除の演算をサポートします。
- **重み平衡木（Weight-Balanced tree）**は平衡二分木の一種です。実装は非破壊的な演算を
  提供します。定数時間の大きさ演算、和集合・積集合・差集合といった多くの高水準な集合
  演算、位置による要素の添字づけを含む、包括的な演算の集合があります。

## 11.1 連想リスト

**連想リスト（association list）**、すなわち **alist** は、Scheme で非常によく使われる
データ構造です。alist はペアのリストで、その各ペアを**連想（association）**と呼びます。
連想の car を**キー（key）**と呼びます。

alist 表現の利点は、alist が新しい項目を前に加えるだけで漸増的に拡張できることです。
さらに、探索手続き `assv` などが alist を順に探索するので、新しい項目が古い項目を
「覆い隠す（shadow）」ことができます。alist をキーからデータへの写像とみなすなら、
alist の前に新しい項目を加えることで、写像を拡張するだけでなく、非破壊的な形で変える
こともできます[^1]。

#### `alist? object` 〔手続き＋〕

`object` が連想リスト（空リストを含む）なら `#t` を、そうでなければ `#f` を返します。
この述語を満たすオブジェクトは `list?` も満たします。

#### `assq object alist` 〔手続き〕
#### `assv object alist` 〔手続き〕
#### `assoc object alist` 〔手続き〕

これらの手続きは、car フィールドが `object` である `alist` の最初のペアを見つけ、その
ペアを返します。返されるペアはつねに `alist` の要素であって、`alist` を構成するペアの
1つではありません。`alist` のどのペアも car に `object` を持たなければ、`#f`（念のため:
空リストではありません）が返されます。`assq` は `object` を `alist` のペアの car フィールド
と比較するのに `eq?` を、`assv` は `eqv?` を、`assoc` は `equal?` を使います[^2]。

```scheme
(define e '((a 1) (b 2) (c 3)))
(assq 'a e)                                     ⇒ (a 1)
(assq 'b e)                                     ⇒ (b 2)
(assq 'd e)                                     ⇒ #f
(assq (list 'a) '(((a)) ((b)) ((c))))           ⇒ #f
(assoc (list 'a) '(((a)) ((b)) ((c)))) ⇒ ((a))
(assq 5 '((2 3) (5 7) (11 13)))                 ⇒ unspecified
(assv 5 '((2 3) (5 7) (11 13)))                 ⇒ (5 7)
```

#### `association-procedure predicate selector` 〔手続き＋〕

`assv` に似た連想手続きを返しますが、`selector`（1引数の手続き）が連想からキーを選ぶ
のに使われ、`predicate`（同値述語）がキーを与えられた項目と比較するのに使われる点が
異なります。これを使えば、要素がペアではなくたとえばベクタである連想リストを作れます
（7.6節「リストの検索」も見よ）。

たとえば、`assv` は次のように実装できたはずです。

```scheme
(define assv (association-procedure eqv? car))
```

もう1つの例は「逆連想（reverse association）」手続きです。

```scheme
(define rassv (association-procedure eqv? cdr))
```

#### `del-assq object alist` 〔手続き＋〕
#### `del-assv object alist` 〔手続き＋〕
#### `del-assoc object alist` 〔手続き＋〕

これらの手続きは、キーが `object` に等しいすべての連想を取り除いた、`alist` の新しく
割り当てられた複製を返します。返される複製は新しく割り当てられたリストですが、リストの
要素である連想ペアは、複製されるのではなく `alist` と共有されることに注意してください。
`del-assq` は `object` をキーと比較するのに `eq?` を、`del-assv` は `eqv?` を、
`del-assoc` は `equal?` を使います。

```scheme
(define a
   '((butcher . "231 e22nd St.")
     (baker . "515 w23rd St.")
     (hardware . "988 Lexington Ave.")))

(del-assq 'baker a)
     ⇒
     ((butcher . "231 e22nd St.")
      (hardware . "988 Lexington Ave."))
```

#### `del-assq! object alist` 〔手続き＋〕
#### `del-assv! object alist` 〔手続き＋〕
#### `del-assoc! object alist` 〔手続き＋〕

これらの手続きは、キーが `object` に等しいすべての連想を `alist` から取り除きます。結果
のリストを返します。`del-assq!` は `object` をキーと比較するのに `eq?` を、`del-assv!`
は `eqv?` を、`del-assoc!` は `equal?` を使います。これらの手続きは、それぞれ `del-assq`、
`del-assv`、`del-assoc` に似ていますが、`alist` を破壊的に書き換える点が異なります。

#### `delete-association-procedure deletor predicate selector` 〔手続き＋〕

`del-assv` や `del-assq!` に似た削除手続きを返します。`predicate` と `selector` の引数は
`association-procedure` のものと同じで、`deletor` 引数は手続き `list-deletor`（非破壊的
な削除の場合）か `list-deletor!`（破壊的な削除の場合）のどちらかであるべきです。

たとえば、`del-assv` のありうる実装を挙げます。

```scheme
(define del-assv
  (delete-association-procedure list-deletor eqv? car))
```

#### `alist-copy alist` 〔手続き＋〕

`alist` の新しく割り当てられた複製を返します。これは `list-copy` に似ていますが、
「連想」ペア、すなわちリスト `alist` の要素も複製される点が異なります。`alist-copy` は
次のように実装できたはずです。

```scheme
(define (alist-copy alist)
  (if (null? alist)
       '()
       (cons (cons (car (car alist)) (cdr (car alist)))
               (alist-copy (cdr alist)))))
```

## 11.2 1次元表

**1次元表（1D table）**（「1次元」の表）は連想リストに似ています。連想リストと違って、
1次元表ではキーが弱く保持されます。キーがガベージコレクションされると、表におけるその
連想値は取り除かれます。1次元表は、キーの等価性の比較に `eq?` を使います。

1次元表は、2次元の連想表（11.3節「連想表」を見よ）のより高性能な代わりとして使えること
がよくあります。連想させるキーの1つがベクタのような複合オブジェクトなら、1次元表を
そのベクタのスロットの1つに格納できます。こうした状況では、1次元表の項目にアクセスする
性能は、伝統的な Lisp で属性リストを使うのに匹敵します。

#### `make-1d-table` 〔手続き＋〕

新しく割り当てられた空の1次元表を返します。

#### `1d-table? object` 〔手続き＋〕

`object` が1次元表なら `#t` を、そうでなければ `#f` を返します。この述語を満たす
オブジェクトは `list?` も満たします。

#### `1d-table/put! 1d-table key datum` 〔手続き＋〕

`1d-table` において `key` と `datum` のあいだに連想を作ります。未規定の値を返します。

#### `1d-table/remove! 1d-table key` 〔手続き＋〕

`1d-table` における `key` の連想を取り除き、未規定の値を返します。

#### `1d-table/get 1d-table key default` 〔手続き＋〕

`1d-table` において `key` に連想されたデータを返します。`key` の連想がなければ、`default`
が返されます。

#### `1d-table/lookup 1d-table key if-found if-not-found` 〔手続き＋〕

`if-found` は1引数の手続きでなければならず、`if-not-found` は引数のない手続きでなければ
なりません。`1d-table` が `key` の連想を含めば、`if-found` が連想のデータに対して起動
されます。そうでなければ、`if-not-found` が引数なしで起動されます。どちらの場合も、
起動された手続きの結果が `1d-table/lookup` の結果として返されます。

#### `1d-table/alist 1d-table` 〔手続き＋〕

`1d-table` と同じ情報を含む、新しく割り当てられた連想リストを返します。

## 11.3 連想表

MIT Scheme は、ほかのたいていの Lisp の実装にある属性リストの仕組みの一般化、すなわち
大域的な2次元の連想表を提供します。この表は2つのキーで添字づけられます。以下の手続きの
説明では `x-key` と `y-key` と呼びます。これらのキーと、それらに連想されるデータは、任意
のオブジェクトでよいです。キーの弁別には `eq?` が使われます。

連想表を行列と考えてください。両方のキーを使って単一のデータにアクセスでき、`x-key`
だけで列に、`y-key` だけで行にアクセスできます。

#### `2d-put! x-key y-key datum` 〔手続き＋〕

`datum` を `x-key` と `y-key` に連想させる項目を連想表に作ります。未規定の結果を返し
ます。

#### `2d-remove! x-key y-key` 〔手続き＋〕

連想表が `x-key` と `y-key` の項目を持てば、それを取り除きます。未規定の結果を返します。

#### `2d-get x-key y-key` 〔手続き＋〕

`x-key` と `y-key` に連想されたデータを返します。そのような連想がなければ `#f` を返し
ます。

#### `2d-get-alist-x x-key` 〔手続き＋〕

`x-key` に連想された、連想表のすべての項目の連想リストを返します。結果は `(y-key .
datum)` のペアのリストです。`x-key` の項目がなければ空リストを返します。

```scheme
(2d-put! 'foo 'bar 5)
(2d-put! 'foo 'baz 6)
(2d-get-alist-x 'foo)                    ⇒ ((baz . 6) (bar . 5))
```

#### `2d-get-alist-y y-key` 〔手続き＋〕

`y-key` に連想された、連想表のすべての項目の連想リストを返します。結果は `(x-key .
datum)` のペアのリストです。`y-key` の項目がなければ空リストを返します。

```scheme
(2d-put! 'bar 'foo 5)
(2d-put! 'baz 'foo 6)
(2d-get-alist-y 'foo)                    ⇒ ((baz . 6) (bar . 5))
```

## 11.4 ハッシュ表

ハッシュ表は、大量の連想を格納する、速く強力な仕組みです。MIT Scheme のハッシュ表は、
自動的なサイズ変更、カスタマイズ可能な成長パラメータ、カスタマイズ可能なハッシュ手続き
を備えています。

ハッシュ表の挿入・削除・探索の演算の平均時間は定数で抑えられます。表が必要とする空間は
表の連想の数に比例します。比例定数は下で説明します（11.4.3節「ハッシュ表のサイズ変更」
を見よ）。

ハッシュ表の実装は、実行時に読み込めるオプションです。ハッシュ表を使うには、ここで定義
する手続きを呼ぶ前に一度、次を実行します。

```scheme
(load-option 'hash-table)
```

### 11.4.1 ハッシュ表の構築

次のいくつかの手続きはハッシュ表のコンストラクタです。すべてのハッシュ表コンストラクタ
は、1つの省略可能引数 `initial-size` を受け取り、新しく割り当てられたハッシュ表を返す
手続きです。`initial-size` が与えられれば、正確な非負整数か `#f` でなければなりません。
`initial-size` の意味は下で説明します（11.4.3節「ハッシュ表のサイズ変更」を見よ）。

ハッシュ表はふつう2つのことで特徴づけられます。キーの比較に使われる同値述語と、表が
そのキーをガベージコレクタに回収させるかどうかです。表がそのキーをガベージコレクタに
回収されるのを妨げるなら、キーを**強く（strongly）**保持するといいます。そうでなければ
キーを**弱く（weakly）**保持するといいます（10.7節「弱いペア」を見よ）。

#### `make-eq-hash-table [initial-size]` 〔手続き＋〕

任意のオブジェクトをキーとして受け取り、それらのキーを `eq?` で比較する、新しく割り
当てられたハッシュ表を返します。キーは弱く保持されます。これらは標準のハッシュ表の中で
もっとも速いものです。

#### `make-eqv-hash-table [initial-size]` 〔手続き＋〕

任意のオブジェクトをキーとして受け取り、それらのキーを `eqv?` で比較する、新しく割り
当てられたハッシュ表を返します。キーは弱く保持されますが、真偽値・文字・数は強く保持
されます。これらのハッシュ表は `make-eq-hash-table` が作るものより少し遅いです。

#### `make-equal-hash-table [initial-size]` 〔手続き＋〕

任意のオブジェクトをキーとして受け取り、それらのキーを `equal?` で比較する、新しく
割り当てられたハッシュ表を返します。キーは強く保持されます。これらのハッシュ表は
`make-eq-hash-table` が作るものよりかなり遅いです。

#### `make-string-hash-table [initial-size]` 〔手続き＋〕

文字列をキーとして受け取り、それらを `string=?` で比較する、新しく割り当てられたハッシュ
表を返します。キーは強く保持されます。

次の2つの手続きは、新しいハッシュ表コンストラクタを作るのに使われます。上のハッシュ表
コンストラクタはすべて、`make-eqv-hash-table` を例外として、これらの「コンストラクタの
コンストラクタ」の呼び出しで作れたはずです。下の例を見よ。

#### `strong-hash-table/constructor key-hash key=? [rehash-after-gc?]` 〔手続き＋〕
#### `weak-hash-table/constructor key-hash key=? [rehash-after-gc?]` 〔手続き＋〕

これらの手続きはそれぞれ2つの引数を受け取り、ハッシュ表コンストラクタを返します。`key=?`
引数はハッシュ表のキーの同値述語です。`key-hash` 引数はハッシュ番号を計算する手続きです。
具体的には、`key-hash` は2つの引数、キーと正確な正整数（法）を受け取り、法より小さい
正確な非負整数を返します。

省略可能引数 `rehash-after-gc?` が真なら、`key-hash` が返す値がガベージコレクションの
あとに変わるかもしれないことを言います。そうなら、ハッシュ表の実装は、必要なときに表を
再ハッシュするよう手配します。（この性質を持つハッシュ手続きについては、11.4.4節「アドレス
ハッシング」を見よ。）そうでなければ、`key-hash` は同じ引数についてつねに同じ値を返すと
仮定されます。この引数の既定値は `#f` です。

`strong-hash-table/constructor` が返すコンストラクタは、キーを強く保持するハッシュ表を
作ります。`weak-hash-table/constructor` が返すコンストラクタは、キーを弱く保持する
ハッシュ表を作ります。

いくつかの標準のハッシュ表コンストラクタがどう定義できたはずかを示す例を挙げます。

```scheme
(define make-eq-hash-table
   (weak-hash-table/constructor eq-hash-mod eq? #t))

(define make-equal-hash-table
  (strong-hash-table/constructor equal-hash-mod equal? #t))

(define make-string-hash-table
   (strong-hash-table/constructor string-hash-mod string=? #f))
```

次の手続きは、弱いハッシュ表と一緒に使うとときに役立ちます。ふつうは必要ありません。
そのようなハッシュ表は、使われるにつれて自動的に自身を掃除するからです。

#### `hash-table/clean! hash-table` 〔手続き＋〕

`hash-table` がキーを弱く保持する種類のハッシュ表なら、この手続きは、ガベージコレクタに
回収されたオブジェクトの連想を記録するのに使われていた空間を回収します。そうでなければ、
この手続きは何もしません。どちらの場合も、未規定の結果を返します。

### 11.4.2 ハッシュ表の基本操作

この節で説明する手続きは、ハッシュ表の基本的な演算です。プログラマがもっともよく必要と
する機能を提供します。以降の節では、いくつかのアプリケーションが必要とする追加の機能を
提供する、他の演算を説明します。

#### `hash-table? object` 〔手続き＋〕

`object` がハッシュ表なら `#t` を、そうでなければ `#f` を返します。

#### `hash-table/put! hash-table key datum` 〔手続き＋〕

`hash-table` において `datum` を `key` に連想させ、未規定の結果を返します。この演算が
必要とする平均時間は定数で抑えられます。

#### `hash-table/get hash-table key default` 〔手続き＋〕

`hash-table` において `key` に連想されたデータを返します。`key` の連想がなければ、
`default` が返されます。この演算が必要とする平均時間は定数で抑えられます。

#### `hash-table/remove! hash-table key` 〔手続き＋〕

`hash-table` が `key` の連想を持てば、それを取り除きます。未規定の結果を返します。この
演算が必要とする平均時間は定数で抑えられます。

#### `hash-table/clear! hash-table` 〔手続き＋〕

`hash-table` のすべての連想を取り除き、未規定の結果を返します。この演算が必要とする平均
時間と最悪時間は定数で抑えられます。

#### `hash-table/count hash-table` 〔手続き＋〕

`hash-table` の連想の数を正確な非負整数として返します。`hash-table` がキーを弱く保持
するなら、これは控えめな上界で、キーが最近ガベージコレクタに回収された連想をいくつか
数えるかもしれません。この演算が必要とする平均時間と最悪時間は定数で抑えられます。

#### `hash-table->alist hash-table` 〔手続き＋〕

`hash-table` の内容を、新しく割り当てられた alist として返します。alist の各要素はペア
`(key . datum)` で、`key` は `hash-table` のキーの1つ、`datum` はその連想されたデータ
です。この演算が必要とする平均時間と最悪時間は、表の連想の数に対して線形です。

#### `hash-table/key-list hash-table` 〔手続き＋〕

`hash-table` のキーの、新しく割り当てられたリストを返します。この演算が必要とする平均
時間と最悪時間は、表の連想の数に対して線形です。

#### `hash-table/datum-list hash-table` 〔手続き＋〕

`hash-table` のデータの、新しく割り当てられたリストを返します。リストの各要素は
`hash-table` の連想の1つに対応します。表が同じデータの複数の連想を含めば、このリストも
そうなります。この演算が必要とする平均時間と最悪時間は、表の連想の数に対して線形です。

#### `hash-table/for-each hash-table procedure` 〔手続き＋〕

`procedure` は2引数の手続きでなければなりません。`hash-table` の各連想に対して1回
`procedure` を起動し、連想のキーとデータをその順で引数として渡します。未規定の結果を
返します。`procedure` は `hash-table` を書き換えてはなりません。1つの例外として、処理中
の連想を取り除くために `hash-table/remove!` を呼ぶことは許されます。

次の手続きは、いくつかの状況で役立つ `hash-table/get` の別の形です。ふつうは
`hash-table/get` のほうが速いので好ましいです。

#### `hash-table/lookup hash-table key if-found if-not-found` 〔手続き＋〕

`if-found` は1引数の手続きでなければならず、`if-not-found` は引数のない手続きでなければ
なりません。`hash-table` が `key` の連想を含めば、`if-found` が連想のデータに対して起動
されます。そうでなければ、`if-not-found` が引数なしで起動されます。どちらの場合も、起動
された手続きが生む結果が `hash-table/lookup` の結果として返されます（`hash-table/lookup`
は起動された手続きへ帰着します。すなわちそれを末尾再帰的に呼びます）。この演算が必要と
する平均時間は定数で抑えられます。

### 11.4.3 ハッシュ表のサイズ変更

ふつう、ハッシュ表は必要に応じて自動的に自身のサイズを変えます。このため、プログラマは
表のサイズの管理を気にする必要はありません。ただし、表のサイズに対する限られた制御が
提供されます。これは下で説明します。この説明には、**使用可能サイズ（usable size）**と
**物理サイズ（physical size）**という2つの概念が関わります。これらをこれから定義します。

ハッシュ表の使用可能サイズは、ある時点で表が保持できる連想の数です。表の連想の数が使用
可能サイズを超えると、表は自動的に成長し、連想を保持するのに十分な新しい値へ使用可能
サイズを増やします。

物理サイズは、表の連想を保持するのにどれだけの空間が割り当てられるかを指定する、ハッシュ
表の抽象的な尺度です。物理サイズはつねに使用可能サイズ以上です。物理サイズ自体は興味深く
ありません。ハッシュ表の性能への影響についてのみ興味深いのです。ハッシュ表の探索の平均
性能は定数で抑えられますが、最悪性能はそうではありません。ある数の連想を含む表について、
表の物理サイズを増やすと、平均より悪い性能が起こる確率が下がります。

ハッシュ表の物理サイズは、統計的に連想の数に関係します。ただし、物理サイズに上界と下界を
置くことができ、これから表が使う空間の量を見積もれます。

```scheme
(define (hash-table-space-bounds count rehash-size rehash-threshold)
  (let ((tf (/ 1 rehash-threshold)))
     (values (if (exact-integer? rehash-size)
                     (- (* count (+ 4 tf))
                         (* tf (+ rehash-size rehash-size)))
                     (* count (+ 4 (/ tf (* rehash-size rehash-size)))))
                (* count (+ 4 tf)))))
```

この式が示すのは、「ふつうの」再ハッシュサイズ（すなわち正確な整数でないもの）について、
ハッシュ表が使う空間の量が表の連想の数に比例することです。比例定数は統計的に変わり、
下界は

```scheme
(+ 4 (/ (/ 1 rehash-threshold) (* rehash-size rehash-size)))
```

で、上界は

```scheme
(+ 4 (/ 1 rehash-threshold))
```

です。これらのパラメータの既定値では、それぞれ 4.25 と 5 です。再ハッシュサイズを小さく
するとこれらの界が狭まりますが、サイズ変更に費やす時間が増えます。したがって、再ハッシュ
サイズが表の時間と空間のトレードオフをある程度制御することがわかります。

プログラマは3つのパラメータでハッシュ表のサイズを制御できます。

- 各表の `initial-size` は、表が作られるときに指定できます。
- 各表は、表を成長・縮小させる必要があるときに表のサイズをどう変えるかを指定する、
  **再ハッシュサイズ（rehash size）**を持ちます。
- 各表は、表の物理サイズと使用可能サイズの関係を指定する、**再ハッシュ閾値（rehash
  threshold）**を持ちます。

表が最初に特定の数の項目を含むとプログラマが知っていれば、表が作られるときに
`initial-size` を与えられます。`initial-size` が正確な非負整数なら、ハッシュ表の初期の
使用可能サイズを指定します。表の項目の数が `initial-size` を超えるまで表はサイズを変えず、
その後に自動的なサイズ変更が有効になり、`initial-size` はもはや効果を持ちません。そう
でなく、`initial-size` が与えられないか `#f` なら、表は未規定のサイズに初期化され、
自動的なサイズ変更がただちに有効になります。

再ハッシュサイズは、ハッシュ表がいっぱいになったときに使用可能サイズをどれだけ増やすか
を指定します。正確な正整数か、1 より大きい実数のどちらかです。整数なら、新しいサイズは
古いサイズと再ハッシュサイズの和です。そうでなければ実数で、新しいサイズは古いサイズと
再ハッシュサイズの積です。再ハッシュサイズを増やすと挿入の平均コストが下がりますが、表が
使う空間の平均量が増えます。表の再ハッシュサイズは、表のサイズ変更を最適化するために、
アプリケーションが動的に変えられます。たとえば、既知の期間は表が速く成長し、その後は
サイズが変わらないなら、成長の局面では大きい再ハッシュサイズを、静的な局面では小さい
ものを使うことで、性能が改善するかもしれません。新しく構築されたハッシュ表の既定の再
ハッシュサイズは 2.0 です。

警告: 再ハッシュサイズに正確な正整数を使うのは、ほとんどつねに望ましくありません。この
選択肢は、Common Lisp のハッシュ表の仕組みとの互換性のためだけに提供されています。理由は、
ハッシュ表をサイズ変更する時間のペナルティにあります。ハッシュ表をサイズ変更するのに
必要な時間は、表の連想の数に比例します。このサイズ変更コストは、表を再び成長させる必要が
出る点まで埋めるのに必要な挿入にわたって償却されます。表が連想の数に比例する量だけ成長
するなら、サイズ変更のコストとサイズの増加はどちらも連想の数に比例するので、挿入演算の
償却コストはなお定数で抑えられます。しかし、表が定数の量だけ成長するなら、これは成り立ち
ません。挿入の償却コストは定数で抑えられません。したがって、定数の再ハッシュサイズを使う
と、挿入の平均コストがハッシュ表の連想の数に比例して増えることを意味します。

再ハッシュ閾値は、0（を含まない）から 1（を含む）のあいだの実数で、ハッシュ表の使用可能
サイズと物理サイズの比を指定します。再ハッシュ閾値を小さくすると、平均より悪い挿入・
削除・探索の時間の確率が下がりますが、ある使用可能サイズに対する表の物理サイズが増え
ます。新しく構築されたハッシュ表の既定の再ハッシュ閾値は 1 です。

#### `hash-table/size hash-table` 〔手続き＋〕

`hash-table` の使用可能サイズを正確な正整数として返します。これは `hash-table` が成長
する前に保持できる連想の数です。

#### `hash-table/rehash-size hash-table` 〔手続き＋〕

`hash-table` の再ハッシュサイズを返します。

#### `set-hash-table/rehash-size! hash-table x` 〔手続き＋〕

`x` は正確な正整数か、1 より大きい実数のどちらかでなければなりません。`hash-table` の
再ハッシュサイズを `x` に設定し、未規定の結果を返します。この演算は表の「縮小閾値」を
調整します。連想の数が新しい閾値より少なければ、表は縮小するかもしれません。

#### `hash-table/rehash-threshold hash-table` 〔手続き＋〕

`hash-table` の再ハッシュ閾値を返します。

#### `set-hash-table/rehash-threshold! hash-table x` 〔手続き＋〕

`x` は 0（を含まない）から 1（を含む）のあいだの実数でなければなりません。`hash-table`
の再ハッシュ閾値を `x` に設定し、未規定の結果を返します。この演算は表の使用可能サイズを
変えませんが、ふつう表の物理サイズを変え、表を再ハッシュさせます。

### 11.4.4 アドレスハッシング

この節で説明する手続きは、任意のオブジェクトに対する非常に効率的なキーハッシュ手続きを
作るのに使えます。これらの手続きはすべて、オブジェクトのアドレスをそのハッシュ番号として
使う**アドレスハッシング（address hashing）**に基づきます。アドレスハッシングの大きな
利点は、任意のオブジェクトをハッシュ番号に変換するのが非常に速く、どのオブジェクトでも
同じだけの時間がかかることです。

アドレスハッシングの欠点は、ガベージコレクタがほとんどのオブジェクトのアドレスを変える
ことです。ハッシュ表の実装は、ガベージコレクションが起こったときにアドレスハッシングを
使う表を自動的に再ハッシュすることで、この欠点を補います。したがって、これらの手続きを
キーハッシングに使うには、（「コンストラクタのコンストラクタ」手続きの `rehash-after-gc?`
引数によって）あなたのキーハッシュ手続きが計算するハッシュ番号がガベージコレクションの
あとに再計算されなければならないことを、ハッシュ表の実装に伝える必要があります。

#### `eq-hash object` 〔手続き＋〕
#### `eqv-hash object` 〔手続き＋〕
#### `equal-hash object` 〔手続き＋〕

これらの手続きは `object` のハッシュ番号を返します。結果はつねに非負整数で、`eq-hash`
の場合は非負の fixnum です。それぞれ `eq?`、`eqv?`、`equal?` によって等価な2つの
オブジェクトは、これらの手続きに引数として渡されると、2つの呼び出しのあいだ、および
その最中にガベージコレクタが走らないかぎり、同じハッシュ番号を生みます。

次の手続きは、標準のアドレスハッシュに基づくハッシュ表が使うキーハッシュ手続きです。

#### `eq-hash-mod object modulus` 〔手続き＋〕

この手続きは `make-eq-hash-table` が使うキーハッシュ手続きです。

#### `eqv-hash-mod object modulus` 〔手続き＋〕

この手続きは `make-eqv-hash-table` が使うキーハッシュ手続きです。

#### `equal-hash-mod object modulus` 〔手続き＋〕

この手続きは `make-equal-hash-table` が使うキーハッシュ手続きです。

### 11.4.5 低水準のハッシュ表操作

この節の手続きは、プログラマがハッシュ表の内部構造の一部を制御できるようにします。ふつう、
ハッシュ表はキーとデータのあいだの連想をペアや弱いペアを使って保ちます。これらの手続きは、
連想を保つのに別のデータ構造を使うことをプログラマが指定できるようにします。この節では、
ハッシュ表における連想を表すデータ構造を**エントリ（entry）**と呼びます。

#### `hash-table/constructor key-hash key=? make-entry entry-valid? entry-key entry-datum set-entry-datum! [rehash-after-gc?]` 〔手続き＋〕

ハッシュ表コンストラクタ手続きを作って返します（11.4.1節「ハッシュ表の構築」を見よ）。
引数はハッシュ表の特徴を次のように定めます。

**`key-hash`**
ハッシュ手続き。2つの引数、キーと正確な正整数（法）を受け取り、法より小さい正確な非負
整数を返す手続きです。

**`key=?`**
2つのキーを受け取り、それらが同じキーであるとき、かつそのときにかぎり真である同値述語。
この述語が2つのキーについて真なら、`key-hash` はそれらの各キーについて同じ値を返さなけ
ればなりません（両方の場合で同じ法が与えられたとき）。

**`make-entry`**
キーとデータを引数として受け取り、新しく割り当てられたエントリを返す手続き。

**`entry-valid?`**
エントリを受け取り、そのエントリのキーがガベージコレクタに回収されているとき、かつその
ときにかぎり `#f` を返す手続き。手続きの代わりに `#t` でもよく、これは `(lambda (entry)
#t)` と等価です。

**`entry-key`**
エントリを引数として受け取り、そのエントリのキーを返す手続き。

**`entry-datum`**
エントリを引数として受け取り、そのエントリのデータを返す手続き。

**`set-entry-datum!`**
エントリとオブジェクトを引数として受け取り、そのエントリのデータをそのオブジェクトに
変更し、未規定の結果を返す手続き。

**`rehash-after-gc?`**
省略可能引数で、真なら `key-hash` が返す値がガベージコレクションのあとに変わるかもしれ
ないことを言います。そうなら、ハッシュ表の実装は、必要なときに表を再ハッシュするよう
手配します。（この性質を持つハッシュ手続きについては、11.4.4節「アドレスハッシング」を
見よ。）そうでなければ、`key-hash` は同じ引数についてつねに同じ値を返すと仮定されます。
この引数の既定値は `#f` です。

たとえば、ふつうのハッシュ表のコンストラクタは次のように定義できたはずです。

```scheme
(define (strong-hash-table/constructor key-hash key=?
                                              #!optional rehash-after-gc?)
  (hash-table/constructor key-hash key=?
                              cons #t car cdr set-cdr!
                              (if (default-object? rehash-after-gc?)
                                   #f
                                   rehash-after-gc?)))
(define (weak-hash-table/constructor key-hash key=?
                                     #!optional rehash-after-gc?)
  (hash-table/constructor key-hash key=? weak-cons weak-pair/car?
                          weak-car weak-cdr weak-set-cdr!
                          (if (default-object? rehash-after-gc?)
                              #f
                              rehash-after-gc?)))
```

#### `hash-table/key-hash hash-table` 〔手続き＋〕
#### `hash-table/key=? hash-table` 〔手続き＋〕
#### `hash-table/make-entry hash-table` 〔手続き＋〕
#### `hash-table/entry-valid? hash-table` 〔手続き＋〕
#### `hash-table/entry-key hash-table` 〔手続き＋〕
#### `hash-table/entry-datum hash-table` 〔手続き＋〕
#### `hash-table/set-entry-datum! hash-table` 〔手続き＋〕

各手続きは、`hash-table` を構築するのに使われた対応する引数の値を返します。

次の手続きは、ハッシュ表の内容をエントリの集まりとして返します。エントリを保持する
データ構造は新しく割り当てられますが、エントリ自体は複製されません。ハッシュ表の演算が
これらのエントリを書き換えうるので、表を書き換えつづけながらエントリを保ちたければ、
エントリを複製すべきです。

#### `hash-table/entries-list hash-table` 〔手続き＋〕

`hash-table` のエントリの、新しく割り当てられたリストを返します。

#### `hash-table/entries-vector hash-table` 〔手続き＋〕

`hash-table` のエントリの、新しく割り当てられたベクタを返します。次と等価です。

```scheme
(list->vector (hash-table/entries-list hash-table))
```

## 11.5 オブジェクトハッシング

MIT Scheme のオブジェクトハッシング機構は、任意のオブジェクトに一意なハッシュ番号を生成
する仕組みを提供します。このハッシュ番号は、オブジェクトのアドレスと違って、ガベージ
コレクションで変わりません。オブジェクトハッシング機構はハッシュ表と一緒に使うと役立ち
ますが、他のことにも使えます。とくに、多くのオブジェクトの表示表現の生成に使われます
（14.7節「カスタム出力」を見よ）。

これらの手続きはすべて `table` と呼ばれる省略可能引数を受け取ります。この表は、オブジェクト
と整数の連想を含みます。与えられれば、この引数は `hash-table/make`（下記）が構築する
オブジェクトハッシュ表でなければなりません。与えられなければ、既定の表が使われます。

#### `hash object [table]` 〔手続き＋〕

`hash` は正確な非負整数を `object` に連想させ、その整数を返します。`hash` が以前に
`object` を引数として呼ばれていれば、返される整数は以前の呼び出しが返したものと同じです。
`hash` は、（`eq?` の意味で）異なるオブジェクトが異なる整数に連想されることを保証します。

#### `unhash k [table]` 〔手続き＋〕

`unhash` は正確な非負整数 `k` を取り、その整数に連想されたオブジェクトを返します。`k` に
連想されたオブジェクトがないか、以前に `k` に連想されていたオブジェクトがガベージコレクタ
に回収されていれば、`condition-type:bad-range-argument` 型のエラーが通知されます。言い
換えると、`hash` が以前にあるオブジェクトについて `k` を返し、そのオブジェクトが回収され
ていなければ、それが `unhash` の呼び出しの値です。

`hash` に引数として渡されるオブジェクトは、ガベージコレクタに回収されるのを守られません。
そのオブジェクトへの他のすべての参照が除かれれば、オブジェクトは回収されます。その後、
（いまや回収された）オブジェクトのハッシュ番号で `unhash` を呼ぶと、エラーが通知されます。

```scheme
(define x (cons 0 0))                    ⇒ unspecified
(hash x)                                 ⇒ 77
(eqv? (hash x) (hash x))                 ⇒ #t
(define x 0)                             ⇒ unspecified
(gc-flip)                                ;ガベージコレクションを強制する
(unhash 77)                                error>
```

#### `object-hashed? object [table]` 〔手続き＋〕

この述語は、`object` が連想されたハッシュ番号を持てば真です。そうでなければ偽です。

#### `valid-hash-number? k [table]` 〔手続き＋〕

この述語は、`k` が何らかのオブジェクトに連想されたハッシュ番号なら真です。そうでなければ
偽です。

次の2つの手続きは、オブジェクトハッシング機構への低水準のインタフェースを提供します。

#### `object-hash object [table [insert?]]` 〔手続き＋〕

`object-hash` は `hash` に似ていますが、追加の省略可能引数 `insert?` を受け取る点が
異なります。`insert?` が与えられ `#f` なら、`object-hash` は、表にすでに連想がある場合
にのみ `object` の整数を返します。そうでなければ `#f` を返します。`insert?` が与えられ
ないか `#f` でなければ、`object-hash` はつねに整数を返し、必要なら表に連想を作ります。

`object-hash` はさらに、`#f` を `hash` とは異なる形で扱います。`object-hash` を `#f` を
引数として呼ぶと、`unhash` に渡されたときに `#f` を返すのではなくエラーを通知する整数を
返します。同様に、`valid-hash-number?` はこの整数について `#f` を返します。

#### `object-unhash k [table]` 〔手続き＋〕

`object-unhash` は `unhash` に似ていますが、`k` がどのオブジェクトにも連想されていない
か、以前に回収されたオブジェクトに連想されていたとき、`object-unhash` は `#f` を返す点
が異なります。これは `object-unhash` が返す値に曖昧さがあることを意味します。`#f` が返され
たとき、`k` が `#f` に連想されているのか、どのオブジェクトにもまったく連想されていないのか
を見分ける方法がありません。

最後に、この手続きは新しいオブジェクトハッシュ表を作ります。

#### `hash-table/make` 〔手続き＋〕

この手続きは、上の手続きの省略可能引数 `table` として使うのに適した、新しい空の
オブジェクトハッシュ表を作って返します。返される表は連想を含みません。

## 11.6 赤黒木

平衡二分木は、キーが順序づけられた大きな連想の集合を保つのに役立つデータ構造です。大きな
連想の集合を含むほとんどのアプリケーションはハッシュ表を使うべきですが、二分木の使用から
利益を得られるアプリケーションもあります。二分木はハッシュ表に対して2つの利点を持ちます。

- 二分木の内容は、木の連想の数に比例する時間で、キーでソートされた alist に変換できます。
  ハッシュ表は線形時間でソートされていない alist に変換できますが、それをソートするには
  追加の時間が要ります。
- 2つの二分木は線形時間で等価性について比較できます。一方ハッシュ表はまったく比較でき
  ません。比較の前に alist に変換しなければならず、alist の比較は、alist がソートされて
  いなければ二次です。

MIT Scheme は赤黒木の実装を提供します。赤黒木の平衡アルゴリズムは、木を非常に密に平衡に
保とうとしないので、おおむね良い性能を提供します。木の任意のノードで、ノードの一方の側が
最悪の場合、他方の2倍の高さになりえます。典型的なデータでは、木はともかくかなりよく平衡
を保ちます。

赤黒木は、木の連想の数に比例する空間をとります。現在の実装では、比例定数は連想あたり
8 ワードです。

赤黒木はキーを強く保持します。言い換えると、赤黒木がある与えられたキーの連想を含めば、
そのキーはガベージコレクタに回収されえません。

赤黒木の実装は、実行時に読み込めるオプションです。赤黒木を使うには、ここで定義する手続き
を呼ぶ前に一度、次を実行します。

```scheme
(load-option 'rb-tree)
```

#### `make-rb-tree key=? key<?` 〔手続き＋〕

この手続きは、新しく割り当てられた赤黒木を作って返します。木は連想を含みません。`key=?`
と `key<?` は、2つのキーを比較し、それらが互いに等しいか、より小さいかをそれぞれ判定する
述語です。任意の2つのキーについて、これらの述語のうち高々1つが真です。

#### `rb-tree? object` 〔手続き＋〕

`object` が赤黒木なら `#t` を、そうでなければ `#f` を返します。

#### `rb-tree/insert! rb-tree key datum` 〔手続き＋〕

`rb-tree` において `datum` を `key` に連想させ、未規定の値を返します。`rb-tree` が
すでに `key` の連想を持てば、その連想が置き換えられます。この演算が必要とする平均時間と
最悪時間は、`rb-tree` の連想の数の対数に比例します。

#### `rb-tree/lookup rb-tree key default` 〔手続き＋〕

`rb-tree` において `key` に連想されたデータを返します。`rb-tree` が `key` の連想を含ま
なければ、`default` が返されます。この演算が必要とする平均時間と最悪時間は、`rb-tree` の
連想の数の対数に比例します。

#### `rb-tree/delete! rb-tree key` 〔手続き＋〕

`rb-tree` が `key` の連想を含めば、それを取り除きます。未規定の値を返します。この演算が
必要とする平均時間と最悪時間は、`rb-tree` の連想の数の対数に比例します。

#### `rb-tree->alist rb-tree` 〔手続き＋〕

`rb-tree` の内容を、新しく割り当てられた alist として返します。alist の各要素はペア
`(key . datum)` で、`key` は `rb-tree` のキーの1つ、`datum` はその連想されたデータです。
alist は、`rb-tree` を構築するのに使われた `key<?` 引数に従ってキーでソートされます。この
演算が必要とする時間は、木の連想の数に比例します。

#### `rb-tree/key-list rb-tree` 〔手続き＋〕

`rb-tree` のキーの、新しく割り当てられたリストを返します。リストは、`rb-tree` を構築する
のに使われた `key<?` 引数に従ってキーでソートされます。この演算が必要とする時間は、木の
連想の数に比例します。

#### `rb-tree/datum-list rb-tree` 〔手続き＋〕

`rb-tree` のデータの、新しく割り当てられたリストを返します。リストの各要素は `rb-tree` の
連想の1つに対応するので、木が同じデータの複数の連想を含めば、このリストもそうなります。
リストは、結果に現れないものの、連想のキーでソートされます。この演算が必要とする時間は、
木の連想の数に比例します。この手続きは次と等価です。

```scheme
(lambda (rb-tree) (map cdr (rb-tree->alist rb-tree)))
```

#### `rb-tree/equal? rb-tree-1 rb-tree-2 datum=?` 〔手続き＋〕

`rb-tree-1` と `rb-tree-2` を等価性について比較し、等しいとき、かつそのときにかぎり `#t`
を、そうでなければ `#f` を返します。木は同じ等価述語と順序述語で（`eq?` の意味で同じ）
構築されていなければなりません。木のキーは、木を作るのに使われた `key=?` 述語を使って
比較され、木のデータは同値述語 `datum=?` を使って比較されます。この演算が必要とする最悪
時間は、木の連想の数に比例します。

#### `rb-tree/empty? rb-tree` 〔手続き＋〕

`rb-tree` が連想を含まないとき、かつそのときにかぎり `#t` を返します。そうでなければ `#f`
を返します。

#### `rb-tree/size rb-tree` 〔手続き＋〕

`rb-tree` の連想の数、すなわち正確な非負整数を返します。この演算が必要とする平均時間と
最悪時間は、木の連想の数に比例します。

#### `rb-tree/height rb-tree` 〔手続き＋〕

`rb-tree` の高さ、すなわち正確な非負整数を返します。これは、木の葉から根までのもっとも
長い経路の長さです。この演算が必要とする平均時間と最悪時間は、木の連想の数に比例します。
返される値は次を満たします。

```scheme
(lambda (rb-tree)
  (let ((size (rb-tree/size rb-tree))
        (lg (lambda (x) (/ (log x) (log 2)))))
    (<= (lg size)
        (rb-tree/height rb-tree)
        (* 2 (lg (+ size 1))))))
```

#### `rb-tree/copy rb-tree` 〔手続き＋〕

`rb-tree` の新しく割り当てられた複製を返します。複製はあらゆる点で `rb-tree` と同一です
が、`rb-tree` への変更が複製に影響せず、その逆も同様である点が異なります。この演算が
必要とする時間は、木の連想の数に比例します。

#### `alist->rb-tree alist key=? key<?` 〔手続き＋〕

`alist` と同じ連想を含む、新しく割り当てられた赤黒木を返します。この手続きは次と等価です。

```scheme
(lambda (alist key=? key<?)
  (let ((tree (make-rb-tree key=? key<?)))
    (for-each (lambda (association)
                (rb-tree/insert! tree
                                 (car association)
                                 (cdr association)))
              alist)
    tree))
```

次の演算は、赤黒木の最小と最大のメンバーへのアクセスを提供します。優先度キューを実装
するのに役立ちます。

#### `rb-tree/min rb-tree default` 〔手続き＋〕

`rb-tree` の最小のキーを返します。木が空なら `default` を返します。

#### `rb-tree/min-datum rb-tree default` 〔手続き＋〕

`rb-tree` の最小のキーに連想されたデータを返します。木が空なら `default` を返します。

#### `rb-tree/min-pair rb-tree` 〔手続き＋〕

`rb-tree` の最小のキーを見つけ、そのキーとその連想されたデータを含むペアを返します。木が
空なら `#f` を返します。

#### `rb-tree/max rb-tree default` 〔手続き＋〕

`rb-tree` の最大のキーを返します。木が空なら `default` を返します。

#### `rb-tree/max-datum rb-tree default` 〔手続き＋〕

`rb-tree` の最大のキーに連想されたデータを返します。木が空なら `default` を返します。

#### `rb-tree/max-pair rb-tree` 〔手続き＋〕

`rb-tree` の最大のキーを見つけ、そのキーとその連想されたデータを含むペアを返します。木が
空なら `#f` を返します。

#### `rb-tree/delete-min! rb-tree default` 〔手続き＋〕
#### `rb-tree/delete-min-datum! rb-tree default` 〔手続き＋〕
#### `rb-tree/delete-min-pair! rb-tree` 〔手続き＋〕
#### `rb-tree/delete-max! rb-tree default` 〔手続き＋〕
#### `rb-tree/delete-max-datum! rb-tree default` 〔手続き＋〕
#### `rb-tree/delete-max-pair! rb-tree` 〔手続き＋〕

これらの演算は、上のアクセサとちょうど同じで、最小または最大のキーに連想された情報を
返しますが、同時にそのキーを削除する点が異なります。

## 11.7 重み平衡木

平衡二分木は、順序づけられたオブジェクトの大きな集合や、キーが順序づけられた連想の集合を
保つのに役立つデータ構造です。MIT Scheme は重み平衡二分木の包括的な実装を持ち、大きな
集合体に対する他のデータ構造にはないいくつかの利点があります。

- 挿入・削除・探索といったふつうの要素水準の演算に加えて、集合の積・和・部分集合の検査
  といった集合水準の演算がひとそろいあり、いずれも時間と空間の良い成長オーダーで実装
  されています。これにより、重み平衡木は、関数的に導かれた仕様の高速なプロトタイピングに
  理想的です。
- 木の要素は、キーの順序のもとでの位置で添字づけられ、要素の順序位置も、どちらもほど
  よい効率で判定できます。
- 最小の要素を見つけて取り除く演算があるので、重み平衡木は優先度キューに使うのが簡単
  です。
- 実装は命令的ではなく関数的です。これは、木に連想を「挿入する」ような演算が古い木を
  破壊しないことを意味します。ちょうど `(+ 1 x)` が定数 1 も `x` に束縛された値も書き
  換えないのと同じです。木は参照透過なので、プログラマは木の複製を気にする必要がありま
  せん。参照透過性により、部分木の共有で空間効率を達成できます。

これらの特徴は、重み平衡木を幅広いアプリケーション、とくに多数の集合や離散写像を必要と
するものに適したものにします。少数の大域的なデータベースを持つ、あるいは挿入や探索と
いった要素水準の演算に集中するアプリケーションは、おそらくハッシュ表や赤黒木を使うほうが
よいでしょう。

木の**大きさ（size）**は、それが含む連想の数です。重み平衡二分木は、各ノードの部分木の
大きさを互いに定数係数以内に保つよう平衡されます。これは単一経路の演算（探索や挿入など）
に対数時間を保証します。重み平衡木は、木の連想の数に比例する空間をとります。現在の実装
では、比例定数は連想あたり 6 ワードです。

重み平衡木は、離散集合または離散写像（連想）のどちらの実装にも使えます。集合は、キーに
連想されるデータを無視して実装されます。この方式のもとでは、木に連想があれば、それは
連想のキーが集合のメンバーであることを示します。ふつう `()`、`#t`、`#f` のような値が
キーに連想されます。

多くの演算は、木の引数を集合とみなすか写像とみなすかに応じて、2つの異なる名前で知られる
結果を計算するとみなせます。例は `wt-tree/member?` です。木の引数を集合とみなすときは、
集合のメンバーシップ演算を計算しますが、木を離散写像とみなすときは、`wt-tree/member?`
は写像がその定義域の要素で定義されているかを検査する述語です。このパッケージのほとんどの
名前は、木を集合として解釈することに基づいて選ばれており、それゆえ `wt-tree/defined-at?`
ではなく `wt-tree/member?` という名前です。

重み平衡木の実装は、実行時に読み込めるオプションです。重み平衡木を使うには、ここで定義
する手続きを呼ぶ前に一度、次を実行します。

```scheme
(load-option 'wt-tree)
```

### 11.7.1 重み平衡木の構築

二分木は、木の要素を並べるのに使われるキーに全順序があることを要求します。重み平衡木は
**型（type）**で組織されます。型は順序関係をカプセル化するオブジェクトです。木を作るのは
2段階の過程です。まず、順序を与える述語から木の型を作らなければなりません。次に、木の型
を使って木を作ります。空の木、単一要素の木、あるいは連想リストのような他の集合体構造から
の木です。いちど作られると、木は自身の型を「知って」おり、型は、2つの木を取る演算で木の
あいだの互換性を検査するのに使われます。ふつう、少数の木の型がプログラムの初めに作られ、
プログラムの実行を通じて何度も使われます。

#### `make-wt-tree-type key<?` 〔手続き＋〕

この手続きは、順序述語 `key<?` に基づく新しい木の型を作って返します。`key<?` は全順序で
なければならず、すべてのキー値 `a`、`b`、`c` について次の性質を持ちます。

```scheme
(key<? a a)                               ⇒ #f
(and (key<? a b) (key<? b a))             ⇒ #f
(if (and (key<? a b) (key<? b c))
     (key<? a c)
     #t)                                  ⇒ #t
```

2つのキー値は、`key<?` によってどちらも他方より小さくなければ、等しいと仮定されます。
`make-wt-tree-type` の各呼び出しは互いに異なる値を返し、木はその木の型が `eq?` である
ときにのみ互換です。その帰結として、二分木の演算で使うことを意図した木は、すべて同じ
`make-wt-tree-type` の呼び出しに由来する木の型で作られなければなりません。

#### `number-wt-type` 〔変数＋〕

数値のキーを持つ木のための標準の木の型。`number-wt-type` は次のように定義できたはずです。

```scheme
(define number-wt-type (make-wt-tree-type <))
```

#### `string-wt-type` 〔変数＋〕

文字列のキーを持つ木のための標準の木の型。`string-wt-type` は次のように定義できたはず
です。

```scheme
(define string-wt-type (make-wt-tree-type string<?))
```

#### `make-wt-tree wt-tree-type` 〔手続き＋〕

この手続きは、新しく割り当てられた重み平衡木を作って返します。木は空、すなわち連想を
含みません。`wt-tree-type` は `make-wt-tree-type` を呼んで得た重み平衡木の型です。返され
る木はこの型を持ちます。

#### `singleton-wt-tree wt-tree-type key datum` 〔手続き＋〕

この手続きは、新しく割り当てられた重み平衡木を作って返します。木は単一の連想、すなわち
`datum` を `key` に連想させるものを含みます。`wt-tree-type` は `make-wt-tree-type` を
呼んで得た重み平衡木の型です。返される木はこの型を持ちます。

#### `alist->wt-tree tree-type alist` 〔手続き＋〕

`alist` と同じ連想を含む、新しく割り当てられた重み平衡木を返します。この手続きは次と
等価です。

```scheme
(lambda (type alist)
  (let ((tree (make-wt-tree type)))
    (for-each (lambda (association)
                (wt-tree/add! tree
                              (car association)
                              (cdr association)))
              alist)
    tree))
```

### 11.7.2 重み平衡木の基本操作

この節では、重み平衡木の基本的な木の演算を説明します。これらの演算は、挿入・削除・探索
のふつうの木の演算、いくつかの述語、木の連想の数を判定する手続きです。

#### `wt-tree? object` 〔手続き＋〕

`object` が重み平衡木なら `#t` を、そうでなければ `#f` を返します。

#### `wt-tree/empty? wt-tree` 〔手続き＋〕

`wt-tree` が連想を含まなければ `#t` を、そうでなければ `#f` を返します。

#### `wt-tree/size wt-tree` 〔手続き＋〕

`wt-tree` の連想の数、すなわち正確な非負整数を返します。この演算は定数時間をとります。

#### `wt-tree/add wt-tree key datum` 〔手続き＋〕

`wt-tree` のすべての連想と、`datum` を `key` に連想させたものを含む新しい木を返します。
`wt-tree` がすでに `key` の連想を持っていれば、新しい連想が古いものを上書きします。この
演算が必要とする平均時間と最悪時間は、`wt-tree` の連想の数の対数に比例します。

#### `wt-tree/add! wt-tree key datum` 〔手続き＋〕

`wt-tree` において `datum` を `key` に連想させ、未規定の値を返します。`wt-tree` がすでに
`key` の連想を持てば、その連想が置き換えられます。この演算が必要とする平均時間と最悪時間
は、`wt-tree` の連想の数の対数に比例します。

#### `wt-tree/member? key wt-tree` 〔手続き＋〕

`wt-tree` が `key` の連想を含めば `#t` を、そうでなければ `#f` を返します。この演算が
必要とする平均時間と最悪時間は、`wt-tree` の連想の数の対数に比例します。

#### `wt-tree/lookup wt-tree key default` 〔手続き＋〕

`wt-tree` において `key` に連想されたデータを返します。`wt-tree` が `key` の連想を含ま
なければ、`default` が返されます。この演算が必要とする平均時間と最悪時間は、`wt-tree` の
連想の数の対数に比例します。

#### `wt-tree/delete wt-tree key` 〔手続き＋〕

`wt-tree` のすべての連想を含む新しい木を返しますが、`wt-tree` が `key` の連想を含めば、
それは結果から取り除かれます。この演算が必要とする平均時間と最悪時間は、`wt-tree` の
連想の数の対数に比例します。

#### `wt-tree/delete! wt-tree key` 〔手続き＋〕

`wt-tree` が `key` の連想を含めば、その連想が取り除かれます。未規定の値を返します。この
演算が必要とする平均時間と最悪時間は、`wt-tree` の連想の数の対数に比例します。

### 11.7.3 重み平衡木の高度な操作

以下で、木の大きさはその木が含む連想の数であり、より小さい木はより少ない連想を含みます。

#### `wt-tree/split< wt-tree bound` 〔手続き＋〕

`wt-tree` の連想のうち、`wt-tree` の木の型の順序関係で `bound` より小さいキーを持つもの
だけを、すべて含む新しい木を返します。この演算が必要とする平均時間と最悪時間は、`wt-tree`
の大きさの対数に比例します。

#### `wt-tree/split> wt-tree bound` 〔手続き＋〕

`wt-tree` の連想のうち、`wt-tree` の木の型の順序関係で `bound` より大きいキーを持つもの
だけを、すべて含む新しい木を返します。この演算が必要とする平均時間と最悪時間は、`wt-tree`
の大きさの対数に比例します。

#### `wt-tree/union wt-tree-1 wt-tree-2` 〔手続き＋〕

両方の木のすべての連想を含む新しい木を返します。この演算は非対称です。両方の木が同じキー
の連想を持つとき、返される木はそのキーに `wt-tree-2` のデータを連想させます。したがって、
木を離散写像とみなすなら、`wt-tree/union` は `wt-tree-1` の `wt-tree-2` による写像の上書き
を計算します。木を集合とみなすなら、結果は引数の集合の和です。この演算が必要とする最悪
時間は、両方の木の大きさの和に比例します。一方の木の最小のキーが他方の木の最大のキーより
大きければ、必要な最悪時間は大きいほうの木の大きさの対数に比例します。

#### `wt-tree/intersection wt-tree-1 wt-tree-2` 〔手続き＋〕

`wt-tree-1` の連想のうち、`wt-tree-2` の連想のキーとして現れるキーを持つものだけを、
すべて含む新しい木を返します。したがって、結果の連想されたデータは `wt-tree-1` のもの
です。木が集合として使われているなら、結果は引数の集合の積です。離散写像の演算としては、
`wt-tree/intersection` は `wt-tree-1` の `wt-tree-2` の（定義域への）定義域制限を計算
します。この演算が必要とする最悪時間は、木の大きさの和に比例します。

#### `wt-tree/difference wt-tree-1 wt-tree-2` 〔手続き＋〕

`wt-tree-1` の連想のうち、`wt-tree-2` の連想のキーとして現れないキーを持つものだけを、
すべて含む新しい木を返します。木を集合とみなすなら、結果は引数の非対称な集合の差です。
離散写像の演算としては、`wt-tree-1` の `wt-tree-2` の（定義域の）補集合への定義域制限を
計算します。この演算が必要とする最悪時間は、木の大きさの和に比例します。

#### `wt-tree/subset? wt-tree-1 wt-tree-2` 〔手続き＋〕

`wt-tree-1` の各連想のキーが `wt-tree-2` の何らかの連想のキーであるとき、かつそのときに
かぎり `#t` を、そうでなければ `#f` を返します。集合演算とみなすと、`wt-tree/subset?` は
非真の部分集合の述語です。真の部分集合の述語は次のように構築できます。

```scheme
(define (proper-subset? s1 s2)
   (and (wt-tree/subset? s1 s2)
         (< (wt-tree/size s1) (wt-tree/size s2))))
```

離散写像の演算としては、`wt-tree/subset?` は写像の定義域に対する部分集合の検査です。
最悪の場合、この演算が必要とする時間は `wt-tree-1` の大きさに比例します。

#### `wt-tree/set-equal? wt-tree-1 wt-tree-2` 〔手続き＋〕

`wt-tree-1` のすべての連想について、同じキーを持つ連想が `wt-tree-2` にあり、その逆も
成り立つとき、かつそのときにかぎり `#t` を返します。引数を集合とみなすと、
`wt-tree/set-equal?` は集合の等価の述語です。写像の演算としては、2つの写像が同じ定義域
で定義されているかを判定します。この手続きは次と等価です。

```scheme
(lambda (wt-tree-1 wt-tree-2)
   (and (wt-tree/subset? wt-tree-1 wt-tree-2
         (wt-tree/subset? wt-tree-2 wt-tree-1)))
```

最悪の場合、この演算が必要とする時間は小さいほうの木の大きさに比例します。

#### `wt-tree/fold combiner initial wt-tree` 〔手続き＋〕

この手続きは、逆順の中間順（in-order）走査を使ってすべての連想をまとめることで、`wt-tree`
を畳み込みます。したがって連想は逆順で訪れられます。`combiner` は3引数の手続きです。キー、
データ、そこまでに蓄積された結果です。`combiner` が定数で抑えられる時間をとるなら、
`wt-tree/fold` は `wt-tree` の大きさに比例する時間をとります。ソートされた連想リストは
単純に導けます。

```scheme
(wt-tree/fold (lambda (key datum list)
                      (cons (cons key datum) list))
                   '()
                   wt-tree))
```

連想のデータは次のように合計できます。

```scheme
(wt-tree/fold (lambda (key datum sum) (+ sum datum))
                   0
                   wt-tree)
```

#### `wt-tree/for-each action wt-tree` 〔手続き＋〕

この手続きは `wt-tree` を順に走査し、各連想に `action` を適用します。連想はキーの増加
する順で処理されます。`action` は2引数の手続きで、連想のキーとデータをそれぞれ取ります。
`action` が定数で抑えられる時間をとるなら、`wt-tree/for-each` は `wt-tree` の大きさに
比例する時間をとります。次の例は木を表示します。

```scheme
(wt-tree/for-each (lambda (key value)
                         (display (list key value)))
                      wt-tree))
```

#### `wt-tree/union-merge wt-tree-1 wt-tree-2 merge` 〔手続き＋〕

両方の木のすべての連想を含む新しい木を返します。両方の木が同じキーの連想を持てば、結果の
木でそのキーに連想されるデータは、手続き `merge` をキー、`wt-tree-1` の値、`wt-tree-2`
の値に適用して計算されます。`merge` は次の形です。

```scheme
(lambda (key datum-1 datum-2) ...)
```

あるキーが一方の木にしか現れなければ、その連想は `merge` で処理されずに結果の木に現れ
ます。したがってこの演算が意味をなすには、`merge` が、一方の木で連想が欠けていることに
対応する右単位元と左単位元の両方を持つか、あるいは、たとえば一方の木のすべてのキーが
他方に現れることが分かっている、といった何らかの保証がなければなりません。

`merge` として次はすべてほどよい手続きです。

```scheme
(lambda (key val1 val2) (+ val1 val2))
(lambda (key val1 val2) (append val1 val2))
(lambda (key val1 val2) (wt-tree/union val1 val2))
```

しかし、

```scheme
(lambda (key val1 val2) (- val1 val2))
```

のような手続きは、両方の木に現れるキーのすべての連想についてはデータの引き算になります
が、2番目の木にしか現れないキーの連想は、おそらく意図とは違い、符号反転されずに複製され
ます。プログラマはこれが決して起こらないようにするとよいでしょう。

この手続きは `wt-tree/union` と同じ時間のふるまいを持ちますが、定数係数はわずかに悪い
です。実際、`wt-tree/union` は次のように定義できたはずです。

```scheme
(define (wt-tree/union tree1 tree2)
  (wt-tree/union-merge tree1 tree2
                            (lambda (key val1 val2) val2)))
```

`merge` 手続きは、データがキーに依存しない場合に備えて、キーを引数に取ります。

### 11.7.4 重み平衡木の添字演算

重み平衡木は、木を連想のソートされた並びとみなす演算をサポートします。並びの要素は位置で
アクセスでき、並びにおける要素の位置も判定でき、どちらも対数時間です。

#### `wt-tree/index wt-tree index` 〔手続き＋〕
#### `wt-tree/index-datum wt-tree index` 〔手続き＋〕
#### `wt-tree/index-pair wt-tree index` 〔手続き＋〕

木のキーに対する順序関係のもとでのソートされた並びにおける、`wt-tree` の 0 起点で
`index` 番目の連想を返します。`wt-tree/index` は `index` 番目のキーを、`wt-tree/index-datum`
は `index` 番目のキーに連想されたデータを、`wt-tree/index-pair` は `index` 番目のキーと
そのデータの cons である新しいペア `(key . datum)` を返します。この演算が必要とする平均
時間と最悪時間は、木の連想の数の対数に比例します。

これらの演算は、`index < 0` の場合、または `index` が木の連想の数以上の場合、
`condition-type:bad-range-argument` 型の条件を通知します。木が空なら、無名のエラーを
通知します。

添字づけは、木の中央値と最大のキーを次のように見つけるのに使えます。

```scheme
中央値:      (wt-tree/index wt-tree
                               (quotient (wt-tree/size wt-tree)
                                          2))
最大:        (wt-tree/index wt-tree
                               (- (wt-tree/size wt-tree)
                                   1))
```

#### `wt-tree/rank wt-tree key` 〔手続き＋〕

木の順序関係のもとでのキーのソートされた並びにおける、`key` の 0 起点の位置を判定します。
木が `key` の連想を持たなければ `#f` です。この手続きは正確な非負整数か `#f` のどちらか
を返します。この演算が必要とする平均時間と最悪時間は、木の連想の数の対数に比例します。

#### `wt-tree/min wt-tree` 〔手続き＋〕
#### `wt-tree/min-datum wt-tree` 〔手続き＋〕
#### `wt-tree/min-pair wt-tree` 〔手続き＋〕

木の順序関係のもとで最小のキーを持つ `wt-tree` の連想を返します。`wt-tree/min` は最小の
キーを、`wt-tree/min-datum` は最小のキーに連想されたデータを、`wt-tree/min-pair` は最小
のキーとそのデータの cons である新しいペア `(key . datum)` を返します。この演算が必要と
する平均時間と最悪時間は、木の連想の数の対数に比例します。

これらの演算は、木が空ならエラーを通知します。次のように書けたはずです。

```scheme
(define (wt-tree/min tree)
  (wt-tree/index tree 0))
(define (wt-tree/min-datum tree)
  (wt-tree/index-datum tree 0))
(define (wt-tree/min-pair tree)
  (wt-tree/index-pair tree 0))
```

#### `wt-tree/delete-min wt-tree` 〔手続き＋〕

`wt-tree` の順序関係のもとで最小のキーを持つ連想を除く、`wt-tree` のすべての連想を含む
新しい木を返します。木が空ならエラーが通知されます。この演算が必要とする平均時間と最悪
時間は、木の連想の数の対数に比例します。この演算は次と等価です。

```scheme
(wt-tree/delete wt-tree (wt-tree/min wt-tree))
```

#### `wt-tree/delete-min! wt-tree` 〔手続き＋〕

`wt-tree` の順序関係のもとで最小のキーを持つ連想を取り除きます。木が空ならエラーが通知
されます。この演算が必要とする平均時間と最悪時間は、木の連想の数の対数に比例します。この
演算は次と等価です。

```scheme
(wt-tree/delete! wt-tree (wt-tree/min wt-tree))
```

# 1 概観

このマニュアルは、MIT Scheme のランタイムシステムを詳しく説明したものです。
プログラマのためのリファレンス文書を意図しています。Scheme をどう起動するか、
どう対話するかは扱いません。それは『MIT Scheme User's Manual』の主題です。

この章では Scheme の意味論をまとめ、MIT Scheme のプログラミング環境を簡単に述べ、
言語の構文上・字句上の規約を説明します。以降の章では、特殊形式、数多くのデータ
抽象、入出力の機構を説明します。

このマニュアルを通じて、**標準 Scheme**（standard Scheme）にたびたび言及します。
標準 Scheme とは、William Clinger、Jonathan Rees ほかによる文書『Revised⁴ Report
on the Algorithmic Language Scheme』（R4RS）、あるいは『IEEE Std. 1178-1990, IEEE
Standard for the Scheme Programming Language』が定める言語です（実際、本文書の
いくつかの部分は Revised Report から写したものです）。MIT Scheme は標準 Scheme の
拡張です。

Scheme 言語の意味論上の重要な特徴は次のとおりです。

**変数は静的スコープを持つ**
Scheme は静的スコープ（statically scoped）のプログラミング言語です。これは、変数の
それぞれの使用が、その変数の字句的に見てとれる束縛に結びつくことを意味します。
Algol も静的スコープの言語です。

**型は潜在的である**
Scheme の型は、明示的な型（manifest types）ではなく潜在的な型（latent types）です。
これは、Scheme が型を変数ではなく値（またはオブジェクト）に結びつけることを意味
します。潜在的な型を持つ言語（弱く型付けされた、あるいは動的に型付けされた言語とも
呼ばれます）には、APL、Snobol、その他の Lisp 方言があります。明示的な型を持つ言語
（強く型付けされた、あるいは静的に型付けされた言語とも呼ばれます）には、Algol 60、
Pascal、C があります。

**オブジェクトは無制限の存続期間を持つ**
Scheme の計算のあいだに作られるオブジェクトは、手続きや継続を含め、すべて無制限の
存続期間（unlimited extent）を持ちます。Scheme のオブジェクトが破棄されることは
決してありません。それでもメモリが尽きないのは、あるオブジェクトが将来の計算で
必要になりえなくなったとき、ガベージコレクタがそのオブジェクトの占めていた記憶域を
回収するからです。ほとんどのオブジェクトが無制限の存続期間を持つ言語には、ほかに
APL やその他の Lisp 方言があります。

**適切な末尾再帰**
Scheme は適切に末尾再帰的（properly tail-recursive）です。これは、反復的な計算が、
たとえ構文上は再帰的な手続きで書かれていても、定数の空間で行えることを意味します。
末尾再帰的な実装では、ふつうの手続き呼び出しの仕組みで反復を表せます。特別な反復用
の式は、構文上の便宜のためだけに用意されています。

**手続きはオブジェクトである**
Scheme の手続きはオブジェクトです。これは、手続きを動的に作り、データ構造に格納し、
別の手続きの結果として返す、といったことができることを意味します。このような手続き
オブジェクトを持つ言語には、ほかに Common Lisp や ML があります。

**継続は明示的である**
ほかのたいていの言語では、継続（continuation）は舞台裏で働きます。Scheme では継続は
オブジェクトです。継続を使って、非局所脱出、バックトラック、コルーチンなど、さまざま
な高度な制御構造を実装できます。

**引数は値渡しである**
Scheme の手続きへの引数は値渡し（passed by value）です。これは、手続きが評価の結果を
必要とするかどうかにかかわらず、手続きが制御を得る前に Scheme が引数の式を評価する
ことを意味します。ML、C、APL も値渡しをする言語です。SASL や Algol 60 のような言語
では、値が手続きに必要とされないかぎり、引数の式は評価されません。

Scheme は、プログラムと（その他の）データを記述するのに、括弧で囲んだリストによる
ポーランド記法を使います。Scheme の構文は、たいていの Lisp 方言と同様に、大きな
表現力を備えており、それはおもにその単純さによります。この単純さの重要な帰結として、
Scheme のプログラムやデータが、ほかの Scheme プログラムから一様に扱えるようになって
います。ほかの Lisp 方言と同じく、基本手続き `read` は入力を構文解析します。すなわち、
読み込んだものを字句的にだけでなく構文的にも分解します。

## 1.1 記法上の規約

この節では、本文書の以降で使う記法上の規約を詳しく述べます。

### 1.1.1 エラー

このマニュアルが「エラーが通知される（an error will be signalled）」という言い回し
を使うとき、それは Scheme が `error` を呼ぶこと、すなわちふつうはプログラムの実行を
止めてエラーメッセージを表示することを意味します。

このマニュアルが「それはエラーである（it is an error）」という言い回しを使うとき、
それは指定された動作が Scheme では正しくないが、システムがそのエラーを通知するとは
かぎらないことを意味します。このマニュアルが何かを「〜でなければならない（must
be）」と言うとき、それはその要求を破るとエラーになることを意味します。

### 1.1.2 例

このマニュアルには、式の評価を示す例が数多く出てきます。例には共通の書式があり、
評価される式を左側に、真ん中に「矢印」を、式の値を右側に書きます。たとえば次の
とおりです。

```scheme
(+ 1 2)              ⇒ 3
```

場所が足りないときは、矢印と値を式の下に移すことがあります。値がどうでもよいときは、
矢印と値の両方を省きます。

例がエラーになる評価を示す場合は、`error>` を前に付けてエラーメッセージを示します
（原著では専用の記号を使っていますが、本訳では `error>` で表します）。

```scheme
(+ 1 'foo)           error> Illegal datum
```

表示（printed output）を示す例では、その行を `-|` で示します（原著の表示記号に
あたります）。

```scheme
(begin (write 'foo) 'bar)
     -| foo
     ⇒ bar
```

このマニュアルが、ある式の返す値は**未規定（unspecified）**であると示すとき、それは
その式がエラーを通知せずに何らかのオブジェクトに評価されるが、プログラムはその値に
どんな形であれ依存すべきでないことを意味します。

### 1.1.3 エントリの書式

MIT Scheme の変数・特殊形式・手続きの説明は、それぞれ次の書式の見出し行から始まり
ます。

```text
テンプレート                                                                分類
```

*分類*（category）は、項目の種類（「変数」「特殊形式」「手続き」）と、その項目が標準
Scheme にどう適合するかを、次のように指定します。

- **分類**（印なし）は、その項目が『Revised⁴ Report on the Algorithmic Language
  Scheme』（R4RS）で説明されていることを示します。
- **分類の後ろの `+`**（プラス記号）は、その項目が MIT Scheme の拡張であることを
  示します。

> **本訳のエントリ表記。** 本訳では、各エントリを見出しにし、テンプレート（シグネチャ）
> をコードスパンに入れて訳さず、分類を〔〕で添えます。`+` は `＋` として残します。
> たとえば〔手続き〕は R4RS の手続き、〔手続き＋〕は MIT Scheme が加えた手続きです。

*テンプレート*の形は分類に応じて解釈します。

**変数**
テンプレートは変数の名前だけからなります。

**特殊形式**
テンプレートは特殊形式の構文キーワードから始まり、続いてその特殊形式の構文の記述が
きます。記述は次の規約に従って書かれます。

名前の付いた構成要素は、印刷版マニュアルではイタリック体、Info ファイルでは大文字に
なります。`cond` 特殊形式の `else` キーワードのような「飾り（noise）」のキーワード
は、印刷版マニュアルでは固定幅フォントで組まれます。Info ファイルでは区別されません。
括弧はそれ自身を表します。

水平の省略記号（`…`）は繰り返される構成要素を表します。具体的には、

```text
thing …
```

は `thing` の0回以上の出現を示し、

```text
thing thing …
```

は `thing` の1回以上の出現を示します。

角括弧 `[ ]` は省略可能な構成要素を囲みます。

いくつかの特殊形式（たとえば `lambda`）は、一連の式からなる内部の構成要素を持ちます。
たいていこれらの式は、その特殊形式の記述で指定された条件のもとで順に評価されます。
この式の並びは、ふつうその特殊形式の**本体（body）**と呼ばれます。

**手続き**
テンプレートは、その手続きが束縛されている変数の名前から始まり、続いて手続きの引数の
記述がきます。引数は「ラムダリスト」記法（2.1節「Lambda 式」を見よ）で記述されます。
ただし、省略可能引数を表すのに角括弧を使い、「残余（rest）」引数を表すのに省略記号を
使う点が異なります。

手続きの引数の名前は、印刷版マニュアルではイタリック体、Info ファイルでは大文字に
なります。

引数が Scheme のデータ型を名指すときは、その引数がその型のデータオブジェクトで
なければならないことを示します。たとえば、

#### `cdr pair` 〔手続き〕

これは、標準 Scheme の手続き `cdr` が1つの引数を取り、それがペアでなければならない
ことを示します。

多くの手続きは、引数の型が誤っているとエラーを通知します。ふつうこのエラーは
`condition-type:wrong-type-argument` 型の条件です。

標準のデータ型名（`pair`、`list`、`boolean`、`string` など）に加えて、次の名前も
引数として使われると型の制限を含意します。

- `object`: 任意のオブジェクト
- `thunk`: 引数のない手続き
- `x`、`y`: 実数
- `q`、`n`: 整数
- `k`: 正確な非負整数

いくつか例を挙げます。

#### `list object …` 〔手続き〕

これは、標準 Scheme の手続き `list` が0個以上の引数を取り、そのそれぞれが任意の
Scheme オブジェクトでよいことを示します。

#### `write-char char [output-port]` 〔手続き〕

これは、標準 Scheme の手続き `write-char` が、文字 `char` を伴って呼ばれなければ
ならず、文字と出力ポートを伴って呼んでもよいことを示します。

## 1.2 Scheme の概念

### 1.2.1 変数束縛

構文キーワードでない識別子は、どれも変数として使えます（1.3.3節「識別子」を見よ）。
変数は、値を格納できる場所（location）を名指すことがあります。そうする変数は、その
場所に**束縛されている（bound）**といいます。変数が束縛されている場所に格納された値を、
その変数の**値**と呼びます。（その変数は、値を名指す、あるいは値に束縛されている、と
言われることもあります。）

変数は、束縛されていても値を持たないことがあります。そのような変数は**未代入
（unassigned）**であるといいます。未代入の変数を参照するとエラーになります。この
エラーが通知されるとき、それは `condition-type:unassigned-variable` 型の条件です。
コンパイラがこのエラーを通知するコードを生成しないこともあります。未代入の変数が
役に立つのは、副作用と組み合わせたときだけです（2.5節「代入」を見よ）。

### 1.2.2 環境の概念

**環境（environment）**とは、変数束縛の集合です。ある環境がある変数に対する束縛を
持たないとき、その変数はその環境で**未束縛（unbound）**であるといいます。未束縛の
変数を参照すると、`condition-type:unbound-variable` 型の条件が通知されます。

既存の環境を新しい束縛の集合で拡張することで、新しい環境を作れます。「環境を拡張
する」ことは、環境を書き換えないことに注意してください。むしろ、新しい束縛と古い
束縛を含む新しい環境を作ります。新しい束縛は古い束縛を**覆い隠します（shadow）**。
すなわち、`x` の束縛を含む環境が `x` の新しい束縛で拡張されると、拡張された環境で
`x` を調べたときには新しい束縛だけが見えます。もとの環境を新しい環境の**親（parent）**、
新しい環境をもとの環境の**子（child）**と呼ぶこともあり、新しい環境が古い環境の
束縛を**継承する（inherit）**ということもあります。

手続き呼び出しは環境を拡張します。`let`、`let*`、`letrec`、`do` の式も同様です。
内部定義（2.4.2節「内部定義」を見よ）も環境を拡張します。（実のところ、環境を拡張する
構文はすべて手続き呼び出しで表せるので、環境の拡張の基本的な仕組みは1つしかありま
せん。）トップレベル定義（2.4.1節「トップレベル定義」を見よ）は、既存の環境に束縛を
加えることがあります。

### 1.2.3 初期環境と現在環境

MIT Scheme は、このマニュアルで説明するすべての変数束縛を含む**初期環境（initial
environment）**を用意しています。ほとんどの環境は、究極的にはこの初期環境の拡張です。
Scheme では、プログラムが実行される環境は、実際にはシステムの束縛を含む環境の子
（拡張）です。したがって、システムの名前はプログラムから見えますが、あなたの名前が
システムのプログラムに干渉することはありません。

プログラムのある地点で有効な環境を、その地点での**現在環境（current environment）**と
呼びます。とくに、どの rep ループにも現在環境があります。（rep は「read-eval-print」
の略です。rep ループとは、入力を読み、評価し、結果を表示する Scheme プログラムです。）
トップレベルの rep ループ（Scheme の起動時にいるもの）の環境は、はじめは
`user-initial-environment` ですが、`ge` 手続きで変えられます。新しい rep ループが
作られると、その環境はそれを作るプログラムが決めます。

### 1.2.4 静的スコープ

Scheme はブロック構造を持つ静的スコープの言語です。この点で、Algol や Pascal に
似ており、Common Lisp を除くほとんどの Lisp 方言とは異なります。

Scheme が（動的束縛ではなく）静的スコープであるという事実は、手続きが呼ばれたときに
拡張されて現在環境となる環境が、その手続きが**作られた**環境（すなわちその手続きを
定義する lambda 式が評価された環境）であり、その手続きが**呼ばれる**環境ではない、
ということを意味します。ほかの Scheme の束縛の式はすべて手続きで表せるので、これが
すべての束縛のふるまいを決めます。

トップレベルの rep ループで（初期環境において）次の定義をしたとします。

```scheme
(define x 1)
(define (f x) (g 2))
(define (g y) (+ x y))
(f 5)                                                  ⇒ 3 ; 7 ではない
```

ここで `f` と `g` は初期環境で作られた手続きに束縛されています。Scheme は静的スコープ
なので、`f` からの `g` の呼び出しは、初期環境（`g` が作られた環境）を `y` を 2 に束縛
して拡張します。この拡張された環境では、`y` は 2 で `x` は 1 です。（動的束縛の Lisp
なら、`g` の呼び出しは `f` の呼び出しのあいだ有効な環境を拡張し、そこでは `x` が `f`
の呼び出しによって 5 に束縛されているので、答えは 7 になります。）

静的スコープでは、変数参照がどの束縛を指すかを、プログラムのテキストを見るだけで
判断できることに注意してください。参照される束縛は、プログラムがどう使われるかには
依存しえません。すなわち、環境の入れ子（親子関係）は、プログラムのテキストにおける
束縛の式の入れ子に対応します。（プログラムのテキストとのこのつながりから、静的スコープ
は**字句スコープ（lexical scoping）**とも呼ばれます。）プログラムで変数が束縛される
場所のそれぞれに対して、その束縛が有効なプログラムのテキストの**領域（region）**が
対応します。たとえば、lambda 式が確立する束縛の領域は、その lambda 式の本体の全体
です。各束縛の式の説明が、それが作る束縛の領域が何であるかを説明します。変数の使用
（すなわち変数の参照または代入）は、その使用を領域に含む束縛のうち、もっとも内側の
ものを指します。そのような領域がなければ、その使用は大域環境（global environment）に
おけるその変数の束縛を指します（大域環境はほかのすべての環境の祖先であり、すべての
プログラムがその中に含まれる領域と考えられます）。

### 1.2.5 真と偽

Scheme では、真偽値の真と偽を `#t` と `#f` で表します。ただし、条件テストのためには、
どんな Scheme の値も真偽値として扱えます。このマニュアルは、真として数えられる任意の
Scheme の値を指すのに**真（true）**という語を、偽として数えられる任意の Scheme の値を
指すのに**偽（false）**という語を使います。条件テストでは、`#f` を除くすべての値が真と
して数えられ、`#f` が偽として数えられます（2.7節「条件式」を見よ）。

実装上の注記: MIT Scheme では、`#f` と空リストは同じオブジェクトであり、`#f` の表示
表現はつねに `()` です。これは Scheme 標準に反するので、MIT Scheme は `#f` と空リストを
別のオブジェクトにするよう変更される予定です。

### 1.2.6 外部表現

Scheme の重要な概念の1つが、文字の並びとしてのオブジェクトの**外部表現（external
representation）**です。たとえば、整数 28 の外部表現は文字の並び `28` であり、整数 8 と
13 からなるリストの外部表現は文字の並び `(8 13)` です。

オブジェクトの外部表現は、必ずしも一意ではありません。整数 28 は `#e28.000` や `#x1c`
という表現も持ち、前の段落のリストは `( 08 13 )` や `(8 . (13 . ( )))` という表現も
持ちます。

多くのオブジェクトは標準的な外部表現を持ちますが、手続きや循環データ構造のように、
標準的な表現を持たないものもあります（ただし個々の実装がそれらに表現を定めることは
あります）。

外部表現をプログラムに書けば、対応するオブジェクトが得られます（2.6節「クォート」を
見よ）。

外部表現は入出力にも使えます。手続き `read` は外部表現を構文解析し、手続き `write` は
それを生成します。両者は合わせて、優雅で強力な入出力機構を提供します。

文字の並び `(+ 2 6)` は、整数 8 に評価される式ではありますが、整数 8 の外部表現では
ないことに注意してください。それはむしろ3要素のリストの外部表現であり、その要素は
シンボル `+` と整数 2 および 6 です。Scheme の構文は、式である任意の文字の並びが、
同時に何らかのオブジェクトの外部表現でもある、という性質を持ちます。これは混乱を招く
ことがあります。文脈を離れると、ある文字の並びがデータを表すのかプログラムを表すのか
がはっきりしないことがあるからです。しかしこれは力の源でもあります。プログラムを
データとして、あるいはデータをプログラムとして扱うインタプリタやコンパイラのような
プログラムを書きやすくするからです。

### 1.2.7 型の互いに素な性質

どのオブジェクトも、次の述語のうち高々1つを満たします（ただし例外については1.2.5節
「真と偽」を見よ）。

```scheme
bit-string?         environment?         port?               symbol?
boolean?            null?                procedure?          vector?
cell?               number?              promise?            weak-pair?
char?               pair?                string?
condition?
```

### 1.2.8 記憶モデル

この節では、Scheme の記憶域の使い方を理解するのに使えるモデルを説明します。

変数と、ペア・ベクタ・文字列のようなオブジェクトは、暗黙のうちに場所（location）
または場所の並びを表します。たとえば文字列は、その中の文字の数だけの場所を表します。
（これらの場所は、機械の1ワードにまるごと対応するとはかぎりません。）これらの場所の
1つには `string-set!` 手続きで新しい値を格納できますが、文字列は以前と同じ場所を
表しつづけます。

場所から、変数参照によって、あるいは `car`、`vector-ref`、`string-ref` のような手続き
によって取り出されたオブジェクトは、取り出しの前にその場所に最後に格納されたオブジェクト
と `eqv?` の意味で等価です。

どの場所にも、使用中かどうかを示す印が付いています。使用中でない場所を参照する変数や
オブジェクトは決してありません。本文書が、変数やオブジェクトのために記憶域が割り当てら
れると言うとき、意味しているのは、使用中でない場所の集合から適切な数の場所が選ばれ、
変数やオブジェクトがそれらを表すようにされる前に、選ばれた場所が使用中であると印を
付けられる、ということです。

多くのシステムでは、定数（すなわちリテラルの式の値）が読み出し専用メモリに置かれると
望ましいものです。これを表すには、場所を表すすべてのオブジェクトが、そのオブジェクトが
**可変（mutable）**か**不変（immutable）**かを告げるフラグに結びついている、と想像する
のが便利です。すると、定数と、`symbol->string` が返す文字列とが不変のオブジェクトで
あり、ほかの手続きが作るオブジェクトはすべて可変です。不変のオブジェクトが表す場所に
新しい値を格納しようとするとエラーになります。MIT Scheme のコンパイラはこの性質を利用
して定数を共有しますが、それらの定数は不変ではないことに注意してください。かわりに、
`equal?` である2つの定数は、コンパイルされたコードでは `eq?` でありうるのです。

## 1.3 字句上の規約

この節では、Scheme の字句上の規約を説明します。

### 1.3.1 空白

**空白（whitespace）**文字は、スペース、改行、タブ、改ページです。空白は、プログラムの
読みやすさを高め、必要なときにトークンどうしを区切るために使われます。（**トークン
（token）**とは、識別子や数のような、それ以上分けられない字句の単位です。）空白は
それ以外では意味を持ちません。空白はどの2つのトークンのあいだにも現れてよいですが、
トークンの内部には現れません。空白は文字列の内部にも現れますが、そこでは意味を持ち
ます。

### 1.3.2 区切り文字

すべての空白文字は区切り文字です。加えて、次の文字が区切り文字として働きます。

```text
( ) ; " ' ` |
```

最後に、次の文字も区切り文字として働きます。Scheme がそれらに特別な意味を定めて
いないにもかかわらずです。

```text
[ ] { }
```

たとえば、変数 `name` の値が `"max"` である場合、

```scheme
(list"Hi"name(+ 1 2))                            ⇒ ("Hi" "max" 3)
```

### 1.3.3 識別子

**識別子（identifier）**とは、1つ以上の非区切り文字の並びです。識別子は Scheme
プログラムでいくつかの使われ方をします。

- ある種の識別子は構文キーワードとして使うために予約されています。それらは変数として
  使うべきではありません（初期の構文キーワードの一覧は、1.4.3節「特殊形式の構文」を
  見よ）。
- 構文キーワードでない識別子は、どれも変数として使えます。
- 識別子がリテラルとして、あるいはリテラルの中に現れるときは、シンボルを表します。

Scheme は、ほかのプログラミング言語が許す識別子のほとんどを受け付けます。MIT Scheme
は、標準 Scheme が許すすべての識別子に加えて、さらに多くを許します。

MIT Scheme は、**潜在的な識別子（potential identifier）**を、`#` または `,` のどちらの
文字でも始まらない非区切り文字の並びと定めます。そのような文字の並びのうち、構文的に
妥当な数（第4章「数」を見よ）でないものは、妥当な識別子とみなされます。（最初の文字の
位置を除けば）識別子の中に `#` や `,` が現れるのは合法ですが、それはよくないプログラ
ミング作法であることに注意してください。

識別子の例をいくつか挙げます。

```scheme
lambda                  q
list->vector            soup
+                       V17a
<=?                     a34kTMNs
the-word-recursion-has-many-meanings
```

### 1.3.4 大文字と小文字

Scheme は、文字定数と文字列定数の中を除いて、文字の大文字の形と小文字の形を区別しま
せん。言い換えると、Scheme は大文字小文字を区別しません（case-insensitive）。たとえば
`Foo` は `FOO` と同じ識別子であり、`#x1AB` は `#X1ab` と同じ数です。しかし `#\a` と
`#\A` は異なる文字です。

### 1.3.5 命名規約

**述語（predicate）**とは、つねに真偽値（`#t` または `#f`）を返す手続きです。慣習と
して、述語の名前はふつう `?` で終わります。

**変更手続き（mutation procedure）**とは、データ構造を書き換える手続きです。慣習として、
変更手続きの名前はふつう `!` で終わります。

### 1.3.6 コメント

コメントの始まりはセミコロン（`;`）で示します。Scheme は、セミコロンの現れる行の、
セミコロンから行末までのすべてを無視します。コメント全体は、それを終える改行文字を
含めて、空白として扱われます。

コメントの別の形（**拡張コメント（extended comment）**と呼ばれることもあります）は、
文字 `#|` で始まり、文字 `|#` で終わります。この別の形は MIT Scheme の拡張です。
ふつうのコメントと同様に、拡張コメントの中のすべての文字は、先頭の `#|` と末尾の
`|#` を含めて、空白として扱われます。この形のコメントは複数行にわたってよく、さらに
入れ子にできます（似た構文を持つプログラミング言語 C のコメントとは違います）。

```scheme
;;; これは FACT 手続きについてのコメントです。Scheme は
;;; このコメントの全体を無視します。FACT 手続きは
;;; 非負整数の階乗を計算します。
#|
これは拡張コメントです。
このようなコメントは、コードの断片をコメントアウトするのに便利です。
|#
(define fact
  (lambda (n)
    (if (= n 0)                               ;これはもう1つのコメント:
        1                                     ;基底の場合: 1 を返す
        (* n (fact (- n 1))))))
```

### 1.3.7 追加の記法

次の一覧は、Scheme で使われる追加の記法を説明します。数に使う記法の説明は、第4章
「数」を見よ。

`+ - .`
プラス記号、マイナス記号、ピリオドは数に使われ、識別子の中に現れることもあります。
区切られたピリオド（数や識別子の中に現れないもの）は、ペアの記法と、仮引数リストで
「残余（rest）」引数を示すために使われます（2.1節「Lambda 式」を見よ）。

`( )`
括弧は、グループ化と、リストの記法に使われます（第7章「リスト」を見よ）。

`"`
二重引用符は文字列を区切ります（第6章「文字列」を見よ）。

`\`
バックスラッシュは、文字定数の構文（第5章「文字」を見よ）と、文字列定数の中での
エスケープ文字（第6章「文字列」を見よ）に使われます。

`;`
セミコロンはコメントを始めます。

`'`
単一引用符はリテラルデータを示します。評価を抑制します（2.6節「クォート」を見よ）。

`` ` ``
バッククォートは、ほとんど定数のデータを示します（2.6節「クォート」を見よ）。

`,`
コンマはバッククォートと組み合わせて使われます（2.6節「クォート」を見よ）。

`,@`
コンマにアットマークを続けたものは、バッククォートと組み合わせて使われます（2.6節
「クォート」を見よ）。

`#`
シャープ（またはポンド）記号は、その直後に続く文字に応じて、さまざまな使われ方を
します。

`#t #f`
これらの文字列は真偽値の定数を表します（10.1節「真偽値」を見よ）。

`#\`
この文字列は文字定数を導入します（第5章「文字」を見よ）。

`#(`
この文字列はベクタ定数を導入します（第8章「ベクタ」を見よ）。閉じ括弧 `)` がベクタ
定数を終えます。

`#e #i #b #o #d #l #s #x`
これらの文字列は数の記法に使われます（第4章「数」を見よ）。

`#|`
この文字列は拡張コメントを導入します。コメントは列 `|#` で終わります。この記法は
MIT Scheme の拡張です。

`#!`
この文字列は、少数の名前付き定数を表すために使われます。現在それらは2つ、
`#!optional` と `#!rest` だけで、どちらも lambda 特殊形式で、ある種の引数を「省略
可能」引数や「残余」引数として印を付けるために使われます。この記法は MIT Scheme の
拡張です。

`#*`
この文字列はビット列を導入します（第9章「ビット列」を見よ）。この記法は MIT Scheme
の拡張です。

`#[`
この文字列は、読み込み可能な外部表現を持たないオブジェクトを表すために使われます
（14.7節「カスタム出力」を見よ）。閉じ角括弧 `]` がそのオブジェクトの記法を終えます。
この記法は MIT Scheme の拡張です。

`#@`
この文字列は、オブジェクトをそのハッシュ番号で参照するための便利な省略記法です
（14.7節「カスタム出力」を見よ）。この記法は MIT Scheme の拡張です。

`#= ##`
これらの文字列は、表示出力で循環構造を示す、あるいは入力でそれらを表すために使われる
記法を導入します。この記法は Common Lisp のそれとよく似た働きをし、MIT Scheme の拡張
です。

## 1.4 式

Scheme の**式（expression）**とは、値を返す構文です。式は、リテラル、変数参照、特殊
形式、手続き呼び出しのいずれかでありえます。

### 1.4.1 リテラル式

リテラルの定数は、データの外部表現を使って書けます。一般に、外部表現はクォートされ
なければなりません（2.6節「クォート」を見よ）。しかし、クォートなしで使える外部表現も
あります。

```scheme
"abc"                                           ⇒ "abc"
145932                                          ⇒ 145932
#t                                              ⇒ #t
#\a                                             ⇒ #\a
```

数の定数、文字列の定数、文字の定数、真偽値の定数の外部表現は、その定数自身に評価され
ます。シンボル、ペア、リスト、ベクタはクォートを必要とします。

### 1.4.2 変数参照

識別子（1.3.3節「識別子」を見よ）からなる式は**変数参照（variable reference）**です。
その識別子は、参照される変数の名前です。変数参照の値は、その変数が束縛されている場所
に格納された値です。参照される変数が未束縛または未代入なら、エラーが通知されます。

```scheme
(define x 28)
x                                                 ⇒ 28
```

### 1.4.3 特殊形式の構文

```scheme
(keyword component ...)
```

構文キーワードで始まる括弧付きの式は、**特殊形式（special form）**です。それぞれの
特殊形式は独自の構文を持ち、それはマニュアルの後の方で説明されます。次の一覧は、MIT
Scheme が初期化されたときに定義されているすべての構文キーワードを含みます。

```scheme
access                       define-syntax                 macro
and                          delay                         make-environment
begin                        do                            named-lambda
case                         fluid-let                     or
cond                         if                            quasiquote
cons-stream                  in-package                    quote
declare                      lambda                        scode-quote
default-object?              let                           sequence
define                       let*                          set!
define-integrable            let-syntax                    the-environment
define-macro                 letrec                        unassigned?
define-structure             local-declare                 using-syntax
```

### 1.4.4 手続き呼び出しの構文

```scheme
(operator operand ...)
```

**手続き呼び出し（procedure call）**は、呼ぶべき手続きを表す式（**演算子（operator）**）
と、それに渡すべき引数を表す式（**被演算子（operand）**）とを、単に括弧で囲んで書き
ます。演算子と被演算子の式が評価され、得られた手続きに得られた引数が渡されます。これ
のより完全な説明は、2.1節「Lambda 式」を見よ。

手続き呼び出しの式の別名は**結合（combination）**です。この語は、つねに式を指す点で
より限定的です。「手続き呼び出し」は、手続きを呼ぶ過程を指すこともあります。

ほかのいくつかの Lisp 方言と違って、Scheme はつねに演算子の式と被演算子の式を同じ評価
規則で評価し、評価の順序は未規定です。

```scheme
(+ 3 4)                                          ⇒ 7
((if #f = *) 3 4)                                ⇒ 12
```

いくつもの手続きが、初期環境の変数の値として使えます。たとえば、上の例の加算と乗算の
手続きは、変数 `+` と `*` の値です。新しい手続きは lambda 式を評価して作ります。

演算子が構文キーワードなら、その式は手続き呼び出しとしては扱われません。特殊形式に
なります。したがって、構文キーワードを手続きの名前として使うべきではありません。これ
らのキーワードの1つを手続きに束縛したとすると、その手続きを呼ぶには `apply` を使わ
なければならなくなります。MIT Scheme は、そのような束縛が試みられるとエラーを通知
します。
